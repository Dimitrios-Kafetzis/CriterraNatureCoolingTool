# v1.2 Brief — The UNEP NbS Catalogue, Availability Gating, and Intervention Packages

The implementation brief for v1.2, fixed after the v1.1 release so the largest
change in the tool's history is implemented against settled decisions rather
than re-designed mid-flight. Companion to [DECISIONS.md](DECISIONS.md) (D-038
schedules the release; the rulings this brief needs are listed under *Decisions
still open* below) and [V2-VISION.md](V2-VISION.md).

**This release does not begin with code.** It begins with a review pack the
author approves line by line. That is the first deliverable, and Phase 1's rule
still governs everything downstream: no performance value ships without a
citation, and CI refuses to load configuration that breaks it (D-017).

## Starting state

v1.1 shipped at methodology `2026.08.03`. The typology library holds **14**
fully grounded typologies, each with its own cited °C envelope, suitability
matrix, and co-benefit defaults. The questionnaire asks one `nbs_type`, and one
assessment scores exactly one intervention; comparison is a separate assessment
per option (D-021).

## Scope

### 1. The review pack (first deliverable, approval gate)

No configuration or code changes until this is approved:

1. **Curated entry list** — every one of the 243 entries marked *keep*, *merge*,
   or *drop*, each with its reason. Drops follow the document's own
   disqualifications (D-038 approved this mandate); merges collapse the
   building-scale/individual duplicates to one canonical entry available at
   both scales. Expected result: roughly 170–190 entries.
2. **Cooling archetype set** — the ~15–20 evidence classes, each with a cited
   °C envelope and evidence-confidence rating. The 14 current typologies seed
   this set; new archetypes (constructed wetland, water square, corridor,
   productive green, and so on) require their own literature retrieval and
   bibliography entries before they can carry a value.
3. **Entry → archetype mapping** — every catalogue entry assigned to exactly
   one archetype, with the reasoning recorded in the evidence tables. This is
   the mechanism that keeps 190 entries honest: an entry inherits a *cited*
   envelope and states which evidence class it inherited from, rather than
   pretending to solution-specific evidence that does not exist.
4. **Availability matrix** — assessment scale × site conditions × land use →
   available entries, in full.

### 2. Four new site-characteristic questions

Approved wording and options, driving the gating rules:

| Field | Type | Purpose |
|---|---|---|
| includes railway | yes / no | Green tram corridor, railway green corridor |
| existing woodland or forest | yes / no | Woodland **restoration** types |
| waterfront type | (not answered) / lake / river / dry river / covered river / sea | Water-landscape entries, by category |
| productive-landscape interest | yes / no | Productive landscape scale |

These are questionnaire inputs, so each needs a normalisation entry, a
confidence-slot decision, and a statement of whether it feeds any score beyond
availability. **A gating answer must not silently become a scoring input**
without its own justification.

### 3. Availability gating

| Assessment scale | Available |
|---|---|
| City | Ecological network scale only |
| District | District scale only |
| Neighbourhood | Street, public space, park always; woodland & forest, water landscape, productive landscape conditionally |
| Site | The neighbourhood-scale entries applicable to the land use, plus **all** individual entries |
| Building | Building scale, individual entries for the surrounding plot, and the land-use-specific cross-category entry only (school → schoolyard greening; healthcare → hospital landscape; campus → campus landscape; memorial → memorial landscape) |

Two rulings already given (D-038):

- **Woodland creation types** (microforest, Miyawaki, afforestation, climate
  forest) are available regardless of the existing-woodland answer, subject to
  area. Only *restoration* types require existing woodland.
- **Constructed water features** (constructed wetland, retention pond,
  detention basin, water square) are available regardless of the waterfront
  answer. Only entries acting on an existing water body are gated by it.

Waterfront category then selects within the water-landscape scale: covered
river → daylighted stream; river → river restoration, riparian buffer,
floodplain restoration; lake → urban lake restoration, floating wetland; sea →
living shoreline, coastal park.

Gating is **configuration, not code** — the same rule as every other
methodology value (ARCHITECTURE boundary 1). The frontend computes no
availability rule of its own; it renders what the API serves.

### 4. Multi-intervention packages

Approved semantics (D-038):

- The user may select several simultaneously-available entries.
- Each component is scored individually and shown individually.
- The package's combined °C estimate is **capped at the best-evidenced single
  component's ceiling, never summed** — D-014 already established that no
  retrieved source quantifies super-additive cooling from combining measures,
  and this is that finding applied rather than re-argued.
- Co-benefits take the union (maximum per dimension, each still cited); costs
  sum; suitability flags stay per-component.
- This supersedes the opaque `mixed_nbs_package` typology, which becomes a
  transparent, itemised package instead of a single averaged card.

### 5. Interface

The picker cannot stay 14 flat cards. Category → searchable list, with the
existing D-019 fit annotations preserved and the D-041 explanation popovers
extended to catalogue entries.

## Out of scope

- The map picker and parameter autofill — v1.3 (D-038), deliberately after the
  questionnaire settles.
- Anything in [V2-VISION.md](V2-VISION.md): GIS workflow, multi-site portfolio,
  batch ingestion, multilingual UI, cloud storage.

## Decisions — all settled

Nothing in this brief is open. The review pack raised ten decisions in total and
all ten are ruled:

- **Six structural rulings** in [D-043](DECISIONS.md): the catalogue's three
  levels; the four land-use contexts retired as typologies; city and district
  scales offering packages; productive gating by governance; the urban-forest
  site reading; street typologies as compositions; the existing fourteen keeping
  their cited values.
- **Four implementation rulings** in [D-044](DECISIONS.md): the new questions
  gate but never score; the release is **`v2.0.0`** with explicit draft
  migration; suitability inherits from the archetype with evidence-based
  overrides; package size is unbounded but warned above five components.

**The release is `v2.0.0`, not `v1.2.0`** (D-044.2). The title of this brief is
kept for continuity with the decision log.

## Gates

Unchanged, and they are the reason this release is safe to attempt: 100%
backend coverage, the D-017 evidence gates (every performance value cited,
every citation key resolvable, version lock-step across configuration and
methodology documents), golden scenarios, and the sensitivity analysis
regenerated — this time it **will** move, because the typology library and
possibly the weights change, and the published figures must be re-derived
rather than carried forward.
