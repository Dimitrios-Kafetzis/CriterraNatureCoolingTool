# v2.3 Brief — Example Images: Real Implementations, Bundled and Verified

The brief for the release that shows what an intervention actually looks like.
Companion to [DECISIONS.md](DECISIONS.md) — the rulings are D-051 — and to
[`data/images/ATTRIBUTION.md`](https://github.com/dkafetzis/CriterraNatureCoolingTool/blob/main/data/images/ATTRIBUTION.md),
the attribution document the build script generates, including the honest
coverage table.

**Status: implemented and shipped as package `2.3.0`, methodology deliberately
unchanged at `2026.08.05` — the images are illustrative examples, not
evidence, and nothing they touch is methodology (D-051.6).**

## The feature

Each NbS card in the intervention picker gains a small image affordance.
Clicking it opens a dialog showing a photograph of a **real implementation**
of that kind of NbS, matched to the project's climate zone, with the photo's
location, author, licence, and a link to its source page. An NbS with no
verified example for the project's zone shows **no affordance at all** —
absence is the honest state, not a placeholder.

## Scope, as ruled in D-051

1. **Images attach at (archetype × climate zone), inherited with per-typology
   overrides** (D-051.1) — the D-044.3 pattern applied to pictures; slot space
   ≤108, not 660.
2. **Images are bundled in the wheel** (preamble, D-051.7): hotlinking an
   image host at click-time would be a third-party request from the default
   build, which D-049.1 forbids. `tools/build_images.py` derives ≤800 px WebP
   re-encodes offline from the curation record, checksums recorded, ≤5 MB
   total, enforced by the licence gate.
3. **Licence policy per file** (D-051.3): public domain / CC0, CC BY,
   CC BY-SA only; NC/ND excluded outright; attribution rendered in the
   dialog, not just stored.
4. **Three verifications per image** (D-051.4): licence read from the actual
   file page; depiction confirmed by looking; climate zone reproduced through
   the tool's own bundled Köppen grid — the build refuses an entry whose zone
   does not reproduce.
5. **Strict zone match, no fallback** (D-051.5), and no affordance before the
   zone is answered.
6. **Captions illustrate, never claim** (D-051.6); the alt text is the
   caption verbatim (D-051.8).

## Coverage shipped

22 verified images: 20 of 108 archetype-level slots filled, plus 2
per-typology overrides (`water_square`, `microforest`), spanning 17 of 18
archetypes and all six climate zones. `permeable_shaded_hardscape` shipped empty in every zone —
no photograph survived verification — and partial coverage is expected and
rendered honestly as no affordance (D-051.9). The full filled-and-empty
table lives in the generated attribution document.

## Out of scope

Images in the PDF/XLSX report (the report stays text); deriving **any** input
from any image (D-002, D-047 — an example photo is not a back door to GIS);
user-uploaded photos; any change to autofill, scoring, or the map.

## Gates

All existing gates unchanged — 100% backend coverage, D-017 evidence gates,
golden scenarios, ruff + format, mypy --strict, eslint, prettier, tsc, the
OpenAPI/schema.ts drift gate, strict docs build — plus:

- the **bundled-content licence gate extended** over the image manifest
  (every shipped file declared; NC/ND provably absent; checksums match;
  attribution fields non-empty; the attribution document covers every image
  and states the honest coverage count; ≤5 MB);
- the **wheel smoke check extended** to assert the images and manifest are
  inside the installed artefact and served from it as actual WebP bytes; and
- the **runtime request gate's walkthrough now opens an example-image
  dialog** mid-assessment and still records zero external requests — the
  photograph provably comes from the application's own origin.

**No methodology version bump, stated deliberately rather than out of habit:**
no methodology value moves, no scoring input exists, no storage shape changes
(schema stays 3), and stored results are untouched.
